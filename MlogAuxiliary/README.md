# MlogAuxiliary · 逻辑辅助

在游戏里框选处理器，说一句要什么，剩下的交给本地后端：生成 → 预检 → 审查 → 写入。
不需要手写 mlog，也不需要离开游戏。

```
F3 拖一个框 ──> 描述框 ──> 每台处理器一个作业 ──> 本地 sidecar（模型 + 41 条规则预检）
                                              ──> 面板看着法与成本 ──> 写入处理器
```

当前版本 **0.14.6**。版本演进见 [HISTORY.md](HISTORY.md)。

## 装

两种装法，**选一种，别并用**——同一个 mod id 只加载一个，谁先生效看加载顺序。

| 装法 | 适合 | 做法 |
|---|---|---|
| 安装包 | 常规 | 解压发行包，双击 `安装.bat`，按提示选存档目录（Steam 版会自动识别） |
| 游戏内导入 | 只想装模组 | 游戏主界面 → 模组 → 导入模组 → 选 `MAI-<版本>-mod.zip`（**带 `-mod` 的那个**） |

两种都会带一个自带的后端（`logicd`，约 40 MB）。游戏内导入时后端在 zip 里，第一次进游戏会先解到数据目录
（`<数据目录>/mlogauxiliary/sidecar/<版本>/`），解完自动拉起；磁盘安装则直接用包里的 exe。

安装包会把上一版挪到 `<存档目录>\mod-backups\`（**mods 之外**）——mods 下留两个同名模组时游戏只认其中一个，看起来就像「装了新版却还在跑旧版」。

装完重启游戏。诊断入口：设置 → **Mlog辅助** → 运行环境（版本、sidecar、数据目录一眼可见）。

## 用

### 框选写入（主流程）

1. 按住 **F3** 拖出矩形，把要写逻辑的处理器框进去，松手。
2. 弹出一个描述框：写要它干什么（「铜不够就从容器里补」「每秒刷一次屏」），回车提交。
3. 框内每台处理器各拿到一个作业。框的**右下角**出现徽标，点开是作业管理窗：
   状态、模型回了什么、假定了哪些前提、成本与预检问题。
4. 面板里点**写入**：后端把代码编译成字节载荷，客户端推给服务端，写进处理器。
5. 写入成功后框**不会消失**——它记着这块区域的工作区上下文，可以接着改进；点框角的**取消**或右键徽标才关。

框角的三个按钮（查看 / 取消 / 续聊）和徽标大小可在 设置 → Mlog辅助 → **框选控件** 里按倍率调（0.5×–2.0×）。

**续聊**：框还在的时候，把光标移到框里某一台处理器上，点「续聊」，写一句「再怎样」就行——
它带着这一台上一版的代码和预检问题重新生成（`mode: improve`），同批其它处理器不受影响。
框里有多台时，光标下那台才算数；不带光标就只认「框里只有一台」的情况。

生成时会从 8 条已通过静态检查的样例里挑 3 条相关的给模型参考（阈值计数、周期触发、开关方块、炮塔开火、内存读写、消息板、二选一分支、波次计数），不再是单一样板。

### 工作区快照

一个选框就是一个工作区：写完一次逻辑，区域、描述、上一次的代码和预检问题都还在。

- **继续改进**：在同一区域再框一次，会复用这个工作区，作业带上次的代码与问题（`mode: improve`）。
- **归档 / 恢复 / 释放**：作业管理窗与「工作区快照」对话框里都能做；释放即不再留存上下文。
- **导出 / 导入**：整块工作区可以导出成文本，换存档或分享用。
- 落盘位置：`<数据目录>/mlogauxiliary/workspaces/<id>.json`（保留最近 200 个）。

### 设置 → Mlog辅助

八段，从上到下：

| 段 | 内容 |
|---|---|
| 大模型 | 地址、密钥（默认隐藏，可切换显示）、模型名、启用/停用。启用后描述意图由模型直接写逻辑；未配置时只提示，不生成任何代码 |
| 聊天播报 | **默认关闭**。开启后作业状态按 `<MAI:logic:><Generating>(12,34):…` 直接发成服务器聊天消息（`:logic:` 渲染成逻辑图标，联机客机也能发）；单机没有聊天框，退回屏幕提示 |
| 框选控件 | 框角与徽标的倍率（0.5×–2.0×），点中间格回 1.0× |
| 最近提示 | 留最后一条提示（错误也在这里），点一下复制全文 |
| 快捷动作 | 快检光标下的处理器、复制诊断、打开工作区快照 |
| 本地快检 | 离线静态检查（模组自带的规则副本），不联网、不需要 sidecar |
| 说明 | 热键与流程一句话 |
| 运行环境 | 版本、构建、可达/不可达语句、sidecar 状态、模型档、数据目录、mods 目录 |

### 本地快检

模组里带了一份检查器（`scripts/quickcheck.js` + `scripts/rules.generated.js`），和 Python 侧 `tools/mlogcheck.py`
是同一套规则的两份实现。它的用处是：sidecar 没起来、或者不想等后端时，先在游戏内判一轮明显问题
（跳转越界、死语句、未定义的读、链接名拼错……），结果只列清单，不做生成。

## 它怎么工作

- **后端**（`logicd`）：本地 HTTP 服务，默认 `127.0.0.1:8765`。模组随游戏启动它，端点见 `GET /health`。
- **一次作业**：模组把描述 + 区域快照 POST 给后端 → 模型产出 mlog → 预检（41 条规则 + 成本）→ 签名 → 编译成字节载荷 → 回给模组。
- **签名**：写入前会在逻辑末尾挂一条带 `aigenerated:MAI:<12 位哈希>` 的跳转，注释按行号与语句锚点打包进 token。
  交付物可以随时用 `tools/aigenerated.py verify` 复核，或用 `extract` 取回注释。
- **写入通道**：走原版 `LogicBlock` 的 config 通道（`compress(code, links)`），服务端负责落地。
- **联机**：写入由服务端执行；权限不足时服务端只会把配置改回去，客户端收不到错误——
  所以写入后会回读处理器代码核对，对不上就明确提示「无权限：…… 未生效」。
- **冲突检测**：写入前比对处理器当前代码与链接表，任何一方被改过都先拦一次，再点一次才覆盖。

## 边界

- 蓝图对话（B1–B4）只有方案，未实现。
- 工作区的 sidecar 侧索引（W5）未做：后端目前不知道工作区，改进用的是模组带过来的上一次代码。
- 多处理器协同寻址、跨处理器通信设计未做。
- 撤销只在内存里，不落盘。
- 界面像素位置只能真机看：无头模拟器里 `Vars.ui` 为 null，自检只覆盖「初始化不抛错 + 控件方法存在」。

## 排障

| 现象 | 处理 |
|---|---|
| 作业直接失败：未配置模型 | 设置 → Mlog辅助 → 大模型，填地址/密钥/模型后点「启用模型档」 |
| sidecar 未就绪 | 看运行环境那段的 sidecar 状态；磁盘安装在 `<模组目录>/sidecar/bin/logicd.exe`，导入装在 `<数据目录>/mlogauxiliary/sidecar/<版本>/` |
| sidecar 是旧版本 | 模组连的是运行中的进程，换版本后需要重启游戏（或结束后端进程） |
| 写入后提示「未生效」 | 联机权限问题：需要房主或管理员授权，或者本方队伍 |
| 描述框提交后没反应 | 先看作业管理窗里的失败原因；sidecar 没起时会在描述框下方直接报 |
| 作业失败，想知道为什么 | 面板会写「为什么：…」（连不上 / 端点拒绝 / 空回复 / 被截断…）和「第 N 次调用：…」（模型、预算、耗时、token 数、finish_reason）；空回复多半是代理吞了回复或预算全花在思考上 |
| 8765 上有个旧后端 | 模组会认出自己拉起的旧版本并退役它；如果是别人的进程，只提示不动手 |

## 目录

```
MlogAuxiliary/
  mod.hjson              模组元数据
  scripts/main.js        全部游戏内逻辑（面板、框选、作业、工作区、HUD）
  sidecar/               随包后端（磁盘安装时才有；游戏内导入时在 zip 里）
```

工具链（检查器、模拟器、蓝图生成、打包）在仓库根目录的 `tools/` 与 `tests/`，见 `tools/README.md`。
